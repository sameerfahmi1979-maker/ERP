# AI-MOD-05: quality and operations

This is the local source contract. Installing source files does not activate its database functions, processing profiles, providers, workers, or a production release. AI04 and AI05 require their reviewed coordinated application/database cutover. An absent contract produces matching-release guidance; permission and network errors never authorize fallback.

## Where it is used

- Existing Assistant answers: Report an AI issue, attached to the actual retained answer.
- Existing DMS intake, extraction results, and retained-document preparation: feedback on the original result/job.
- Existing AI Settings: Quality and operations tab. Existing Data Quality, daily dashboard, and DMS observability reuse the same services and permissions.
- Existing document-type preparation profile: exact saved rules/schema/prompt evaluation binding. No replacement administration application or new UI theme.

## Feedback and review

Issue families are wrong person, wrong document, incorrect value, unsupported answer, and missing result. Sharing is opt-in. Feedback never changes business data, trains a model, enables a prompt, or approves a document. It binds the real source, versions, current actor authority and recorded model/prompt/profile provenance; unknown historical provenance stays unknown.

Current source authority is checked before feedback reads, reviews, curation and retries. Global AI configuration access does not confer private conversation or HR/document access. Unclassified HR-answer corrections conservatively require all relevant sensitive HR capabilities for an independent reviewer. Owners require their unchanged authority binding. A revoked source/session or scope change withdraws delivery while preserving history.

Corrections are minimized before storage; native authority also rejects credential/link-shaped input. Do not paste passwords, keys, full documents or unnecessary personal data. Accepted corrections may be explicitly linked to independently approved minimized datasets. Disagreements and rejected feedback remain immutable history and are not silently promoted into training examples.

Feedback, control and evaluation writes retain original operation identities. Double clicks and repeated submissions do not create a new paid workflow. Uncertain responses lock the original payload for recovery; definitive rejection permits correction. Account/scope changes retire visible drafts and late responses. Business references use AI-FB, AI-DS, AI-EV and AI-TURN; UUIDs stay internal.

## Repeatable evaluation

Each dataset code/revision has immutable cases, language, expected facts, evidence references, criticality and a content hash. A different authorized person approves its minimized content. Candidate records retain model, prompt, rules, optional exact document-type/profile/schema binding, observations and a same-dataset approved baseline.

The server recomputes every expected fact/evidence comparison. Missing, duplicated, forged or incomplete cases fail. Individual regressions are retained even if an aggregate improves. A failed/regressed result cannot be approved. A different authorized reviewer approves eligible results.

`synthetic_contract` proves deterministic contracts only. `reviewed_provider_results` records operator-supplied observations from an independently authorized representative evaluation; it requires a model and approved sample/budget reference. This form does not call a paid provider or independently attest the operator's observations. Real model quality, sample approval and budget remain separate human/release gates. Dataset, sample size, run date and approval date label comparisons; provider confidence and review acceptance are not factual accuracy.

An evaluated/approved/active preparation profile must reference its exact eligible independently approved provider-result version. Synthetic checks cannot enable it. The claimed worker verifies both configured and actual returned model/prompt before publishing a candidate. Existing OCR routing remains authoritative; no provider or feature is enabled by this migration.

## Operations and recovery

Existing configuration/observability permissions govern global monitoring and processing controls. Source review remains separately scoped. The panel reads existing usage logs, queue/attempts, profiles, model configuration, index timestamps and pending reviews. It exposes operational aggregates without OCR text, conversation content, credentials or private source hashes. Known USD estimates are partial when prices are missing. Missing tokens remain unknown. Last index update is not proof every source is indexed.

- Assistant: global pause and optional rolling 24-hour turn-admission ceiling, preserving existing time/token limits and a two-model-call ceiling. A turn may span companies, so company ownership is never guessed. No unsupported Assistant monetary budget is claimed.
- DMS queue: global and optional exact-company controls; the stricter applicable hold wins. Rolling attempt ceilings and optional estimated USD reservations use current confirmed model rates. No default budget is invented.
- Finite DMS budgets admit bounded priced text stages using the selected provider configuration and conservative token-price ceiling. Unconfirmed rates, unresolved/unknown costs, unpriced OCR and legacy unquoted jobs are held. Estimates are not provider billing guarantees. Completed stages remain recoverable, including while paused.
- Pause fences new admissions/stages while retaining original jobs, stages, files, attempts and audit. Existing source-authorized retry/cancel controls remain the owning operations. No queue reset, blanket resend, provider replay or worker activation is introduced.
- Completed preparation stages log canonical usage exactly once. Lost stage publication never authorizes repeating an uncertain provider call. Assistant usage is scoped per actor/turn, with actual model/prompt provenance and no raw input/output logs. Logging failure never repeats a confirmed provider request.
- An operator may explicitly hold an unresolved Assistant admission. The actor/time are recorded; other questions may then proceed within limits. Holding never authorizes automatically repeating the uncertain original question.

## Release and acceptance

Required local acceptance includes source review, unit/component/action and actual isolated PostgreSQL RLS tests, independent-review/concurrency/revocation checks, types, lint, production-mode compilation and security checks. JSDOM is component testing, not browser or device acceptance. Visual/keyboard/contrast/zoom/Android acceptance remains owner-pending. No browser/computer control or real provider evaluation follows from these tests.

Do not early-apply AI04/AI05 migrations to the live-data local app while the deployed application is older. A coordinated release must verify migration history, private schema backup/recovery, exact configuration, required business approvals and compatible app/workers before any activation. Public publication, merge, deployment, paid evaluation and production mutation require their own authorization.
